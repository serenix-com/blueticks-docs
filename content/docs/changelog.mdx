## API specification

### 2026-10-09 — spec re-synced with production (no version bump)

The published spec had drifted behind the live API. It is now regenerated from
the production backend, and every route in it was probed on `api.blueticks.co`.

- **New endpoints:** `POST /v1/realtime/token` (MQTT credentials for receiving
  messages without a webhook), `POST /v1/identity/resolve` and
  `GET /v1/identity/{id}` (resolve `@lid` / phone identities), and the
  WhatsApp Business label endpoints `GET /v1/wa-labels`,
  `GET /v1/chats/{chatId}/wa-labels`, `PATCH /v1/chats/{chatId}/wa-labels`
  (scopes `wa-labels:read` / `wa-labels:write`).
- **List endpoints may also return `nextCursor`.** Offset pagination
  (`limit` / `skip` / `total`) is unchanged; some lists (audiences, campaigns,
  scheduled messages, boards, chats, contacts, newsletters) add an optional
  `nextCursor` string when more results exist. `GET /v1/messages/pinned/{chatId}`
  and `POST /v1/messages/acks` return only `{ success, data }` (no
  `limit` / `skip` / `total`).
- **Send and schedule bodies** accept `mentions`, `mediaMimeType`,
  `buttonReply` and `waLabelIds`; `recipientName` can be set when scheduling.
  Scheduled messages now return `recipientName` and `waLabels`.
- **Webhooks** return `signingSecret`, and the spec's `events` enum now lists every
  supported event (message, session, campaign and the `*_webhook` engine events
  already described in [Webhooks](/docs/webhooks)).
- **Query parameters** added to `GET /v1/chats`, `GET /v1/messages`,
  `GET /v1/latest-chats`, `GET /v1/scheduled-messages`,
  `GET /v1/chats/{chatId}/participants` and
  `GET /v1/contacts/{id}/common_groups` (e.g. `engine`, `engineId`, `limit`,
  `skip`); see each reference page.
- **Errors** also carry `error.requestId` (camelCase) next to `error.request_id`,
  and rate-limit/plan errors may include `error.upgrade`.
- **`POST /v1/suno/songs`:** `lyrics` is no longer required (only `style`).
- **Recipient in the path:** `POST /v1/scheduled-messages` without a chat id
  returns `410`; use `POST /v1/scheduled-messages/{chatId}`.

### v2.0.0 — 2026-06-06 (breaking)

- **Pagination switched from cursor to offset.** Every list endpoint now takes
  `limit` + `skip` and returns `{ data[], limit, skip, total }`. The previous
  `cursor` query param and the `has_more` / `next_cursor` response fields are
  removed. `total` is the full count of matching items across all pages.
- **All responses now carry a `success` flag.** Success responses are
  `{ success: true, ... }` — list endpoints add `data`/`limit`/`skip`/`total`,
  and single-resource / create / update responses nest the payload under
  `data` (`{ success: true, data: {...} }`). Errors are
  `{ success: false, error: { code, message, request_id } }`.

### v1.0.0 — 2026-04-23

- Initial public release.
- Endpoints: `GET /v1/ping`, `GET /v1/account`.
- Error envelope contract locked (see [Errors & retries](/docs/errors)).

### v4.0.0 (Python · Node) / v5.0.0 (PHP) / v2.0.0 (Ruby · Go) — 2026-05-27 (breaking)

- **Pagination switched from cursor to offset**, matching **API v2.0.0**:
  list calls now take `limit` + `skip` and return
  `{ data[], limit, skip, total }`. Replace any loop that read `has_more` /
  `next_cursor`.
- **`delete()` now returns a typed `{ id, deleted: true }` resource** instead
  of `void`.

### Ruby & Go SDKs — 2026-05-01

- **Two new official SDKs joined the family:** Ruby (`gem install blueticks`)
  and Go (`go get github.com/serenix-com/blueticks-go`). Both expose the same
  resources as the other clients, in each language's idiomatic style — Ruby with
  keyword args (`client.scheduled_messages.create(...)`), Go with `context.Context`
  and typed param structs (`client.Chats.SendMessage(ctx, ...)`). See the
  [Quickstart](/docs/quickstart) and any [API Reference](/docs/api) page for
  per-endpoint examples in all five languages.

### v3.1.0 — 2026-04-25 (Node.js only)

- `BluetickError.details` field surfaces backend Zod validation issues
  with per-issue `{path, code, message}`. Existing `try/catch` code
  keeps working; the new field is additive.

### v3.0.0 — 2026-04-25 (Python · Node · PHP)

- WhatsApp tools: `chats`, `groups`, `contacts`, `engines`, `utils`
  resources land alongside the existing `messages` / `audiences` /
  `campaigns` / `webhooks` set.

### v2.0.0 — 2026-04-24 (Python · Node · PHP)

- Cursor pagination across all list endpoints. Replaces page-number
  pagination. Calls return `{data[], has_more, next_cursor}`; pass
  `cursor` back to fetch the next page.

### v1.0.0 — 2026-04-23

- Initial public release of all three SDKs alongside the v1 API spec.

## MCP server

### v0.1.0 — 2026-04-25

- Initial release of `@blueticks/mcp` — local stdio MCP server wrapping
  the Node SDK. Exposes 9 tools, one per Blueticks resource
  (`scheduled_messages`, `chats`, `groups`, `audiences`, `campaigns`,
  `contacts`, `engine`, `webhooks`, `utils`). See [MCP server](/docs/mcp)
  for setup and the authoritative tool list.
